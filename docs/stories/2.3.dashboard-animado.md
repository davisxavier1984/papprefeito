# Story 2.3: Dashboard animado (cards, contadores, barras e skeletons)

## Status

Draft

## Story

**As a** gestor municipal consultando o financiamento da APS,
**I want** ver um esqueleto do painel enquanto a consulta roda e, quando os dados chegam, os cards de métricas e de programas aparecendo em sequência com os valores em R$ "contando" até o total,
**so that** eu saiba que o sistema está trabalhando e perceba rapidamente quais números mudaram após cada consulta ou edição.

## Acceptance Criteria

1. **Skeleton na primeira consulta:** enquanto `isLoading` do `municipioStore` for verdadeiro e ainda não houver dados (`useHasDados() === false`), o Dashboard exibe skeletons (Ant Design `Skeleton`) no formato de 4 cards de métricas + área de tabela, em vez do estado vazio "Nenhum dado carregado ainda".
2. **Reconsulta:** quando já há dados e uma nova consulta é disparada, MetricsCards, ProgramasCards e AnaliseBox ficam visualmente marcados como "atualizando" (opacidade reduzida + `aria-busy="true"` no contêiner) até a resposta chegar; os dados antigos não somem abruptamente.
3. **Entrada escalonada:** ao exibir novos dados, os 4 cards de `MetricsCards` e os cards de cada seção de `ProgramasCards` entram com `staggerContainer`/`staggerItem` (fade + deslocamento ≤ 8 px, 200 ms por item, intervalo de 50 ms, total da sequência ≤ 600 ms). A animação de entrada roda na chegada de uma nova consulta, **não** a cada edição de perda na tabela.
4. **Contador numérico:** valores monetários de `MetricsCards` (Perda Mensal Total, Diferença Anual, Total Recebido) e o percentual de perda animam do valor anterior ao novo em ≤ 600 ms, sempre formatados em pt-BR (`R$ 1.234,56`; `12,34 %` conforme `Intl.NumberFormat('pt-BR')`), sem "pular" de largura (usar `font-variant-numeric: tabular-nums`). O valor final exibido é idêntico ao formatado hoje.
5. Leitores de tela recebem apenas o valor final (o número intermediário fica `aria-hidden`, com texto final em elemento visualmente oculto ou `aria-label`).
6. **ProgressBar animada:** a barra de `Programas/ProgressBar.tsx` cresce de 0 até o percentual (≤ 300 ms, usando `scaleX` em vez de `width`), mantém as cores atuais por faixa e expõe `role="progressbar"` com `aria-valuenow`, `aria-valuemin=0`, `aria-valuemax=100` e `aria-label` (ex.: "12 de 15 credenciados").
7. Com `prefers-reduced-motion: reduce`: sem stagger nem deslocamento, contador mostra o valor final imediatamente, barra aparece já preenchida; skeletons continuam aparecendo (o `active`/shimmer do Skeleton é desligado).
8. Formatadores de moeda de `ProgramaCard.tsx` e `AnaliseBox.tsx` passam a usar uma instância de módulo compartilhada (`src/utils/format.ts`), sem mudar o texto exibido.
9. **Funcionalidade existente continua igual:** consulta de município, edição de perdas com autosave (as métricas continuam recalculando a cada edição), geração dos dois PDFs (botões e mensagens), login e admin.
10. `npx tsc -b` passa; lint dos arquivos alterados sem novos erros (projeto ≤ 16); build de verificação em `/tmp` com tamanho registrado.
11. Plano de rollback documentado (Dev Notes).

## Dev Notes

### Dependências
- Story 2.1: `src/theme/motion.ts` (`staggerContainer`, `staggerItem`, `durations.counter`, `transitions`) e `MotionConfig reducedMotion="user"`.
- Story 2.2: transição de rota já cuida da entrada da página — **não** adicionar outra animação no contêiner raiz do Dashboard (a classe `fade-in-up` foi removida em 2.2).

### Fluxo de dados (não alterar)
- A consulta é disparada em `Sidebar.tsx:41-43` / `CompetenciaInput.tsx` via `hooks/useConsultarDados.ts`, que chama `setLoading(true)` em `onMutate` (`:61-64`) e `setLoading(false)` em `onSettled` (`:86-88`).
- `stores/municipioStore.ts:201-224` (`calcularResumoFinanceiro`) recalcula `resumoFinanceiro` **a cada edição** de perda. Portanto `MetricsCards` re-renderiza a cada commit do `CurrencyInput`: o contador deve animar do valor anterior ao novo, mas o stagger de entrada **não** deve repetir (use `key` de consulta, não de valores).
- `useHasDados()` (`municipioStore.ts:281-288`) só é verdadeiro após `dadosFinanciamento` com `resumosPlanosOrcamentarios` não vazio.

### Esboço do contador
```tsx
import { animate, useMotionValue, useMotionValueEvent, useReducedMotion } from 'motion/react';
const mv = useMotionValue(value);
const [text, setText] = useState(() => format(value));
const reduce = useReducedMotion();
useMotionValueEvent(mv, 'change', (v) => setText(format(v)));
useEffect(() => {
  if (reduce) { mv.set(value); return; }
  const controls = animate(mv, value, { duration: durations.counter, ease: easings.standard });
  return () => controls.stop();
}, [value, reduce]);
```
Alternativa com melhor desempenho: escrever direto em `ref.current.textContent` no `change`, evitando re-render por frame.

### Restrições
- Não animar nada dentro da `FinancialTable` nesta story (escopo da 2.4).
- Não alterar as cores/semântica "Perda" dos cards nesta story (a contradição de cor com a tabela — achado 14 — é tratada na 2.4).
- Não usar `layout`/`layoutId` em cards dentro de `Row`/`Col` (causa saltos com o grid do AntD).

### Rollback
- `git revert` do commit. Alternativa pontual: trocar `<AnimatedNumber>` de volta pelo `formatter` original e remover os wrappers `motion.div` (os componentes continuam válidos sem eles). `utils/format.ts` pode permanecer (não muda comportamento).
