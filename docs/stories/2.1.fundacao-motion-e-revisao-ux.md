# Story 2.1: Fundação de animações (motion) e registro da revisão de UX

## Status

Draft

## Story

**As a** desenvolvedor do frontend MaisPAP,
**I want** ter os achados da revisão de UX priorizados e uma base única de animação (`motion`, tokens de movimento e suporte a movimento reduzido) configurada na raiz do app,
**so that** as próximas stories do épico EPIC-UX-002 implementem animações consistentes, curtas e acessíveis sem duplicar estilos nem afetar os fluxos existentes.

## Acceptance Criteria

1. Existe o documento `docs/qa/assessments/epic-2-ux-review.md` com os 50 achados da revisão — os 30 da seção "Estado atual" do épico `docs/prd/epic-2-frontend-ux-animacoes.md` e os 20 das telas novas do épico 3 (relatórios em lote, preenchimento automático, valores de referência), revisados em `docs/qa/assessments/2026-09-24-revisao-frontend.md` (seção 2) —, cada um com arquivo:linha reancorado ao HEAD atual, prioridade (Alta/Média/Baixa) e a story que o resolve (2.2–2.5) ou "fora de escopo"/"nova story" com justificativa.
2. A dependência `motion` está instalada em `frontend/package.json` (seção `dependencies`) e todo import do projeto usa `'motion/react'` (nenhum import de `framer-motion`).
3. Existe `frontend/src/theme/motion.ts` exportando: tokens de duração (`fast` 0,15 s, `base` 0,2 s, `slow` 0,3 s), easings (`standard`, `enter`, `exit`), variants reutilizáveis (`fadeIn`, `fadeInUp`, `staggerContainer`, `staggerItem`, `pageTransition`) e o helper `highlightFlash` (cor de destaque para a story 2.4). Nenhuma duração de transição excede 0,3 s (contadores numéricos terão token próprio `counter` ≤ 0,6 s).
4. `App.tsx` envolve a aplicação em `<MotionConfig reducedMotion="user" transition={...token base}>` sem alterar a ordem/semântica dos providers existentes (`QueryClientProvider` → `ConfigProvider` → `AntApp` → `BrowserRouter`). **Decisão tomada nesta story (antecipando a 2.5):** usar `<LazyMotion features={domAnimation} strict>` dentro do `MotionConfig` desde já, e todas as stories seguintes (2.2–2.5) usam o componente `m` de `'motion/react'` em vez de `motion` (o modo `strict` gera erro em desenvolvimento se algum `motion.*` for usado por engano).
5. As animações CSS legadas respeitam movimento reduzido: `App.css` recebe `@media (prefers-reduced-motion: reduce)` desativando `.fade-in-up` (e qualquer `transition` de deslocamento criada no épico).
6. Com `prefers-reduced-motion: reduce` ativo no sistema/DevTools, nenhuma animação de deslocamento/escala é executada; sem a preferência, o comportamento visual atual é mantido (esta story não adiciona animações visíveis novas além do wiring).
7. **Funcionalidade existente continua igual:** consulta de município (UF → município → competência → Consultar Dados), edição de perdas com `CurrencyInput` + autosave (debounce 2 s), geração dos dois PDFs, login/registro/logout e a página `/admin/users` funcionam exatamente como antes.
8. `npx tsc -b` passa; `npx eslint` nos arquivos alterados não introduz erros novos (o projeto permanece com no máximo 16 erros pré-existentes); build de verificação em pasta separada conclui e o aumento do bundle é registrado no Dev Agent Record.
9. Plano de rollback documentado e testado (ver Dev Notes → Rollback).

### Esqueleto sugerido de `src/theme/motion.ts`
```ts
import type { Transition, Variants } from 'motion/react';

export const durations = { fast: 0.15, base: 0.2, slow: 0.3, counter: 0.6 } as const;

export const easings = {
  standard: [0.2, 0, 0, 1],
  enter: [0, 0, 0.2, 1],
  exit: [0.4, 0, 1, 1],
} as const;

export const transitions: Record<'fast' | 'base' | 'slow', Transition> = {
  fast: { duration: durations.fast, ease: easings.standard },
  base: { duration: durations.base, ease: easings.standard },
  slow: { duration: durations.slow, ease: easings.enter },
};

export const fadeIn: Variants = { hidden: { opacity: 0 }, visible: { opacity: 1 } };
export const fadeInUp: Variants = {
  hidden: { opacity: 0, y: 8 },
  visible: { opacity: 1, y: 0, transition: transitions.base },
};
export const staggerContainer: Variants = {
  hidden: {},
  visible: { transition: { staggerChildren: 0.05, delayChildren: 0.03 } },
};
export const staggerItem = fadeInUp;
export const pageTransition: Variants = {
  initial: { opacity: 0, y: 6 },
  animate: { opacity: 1, y: 0, transition: transitions.base },
  exit: { opacity: 0, transition: transitions.fast },
};
/** Cor de destaque (fundo) para feedback de edição — story 2.4 */
export const highlightFlash = { from: 'rgba(14, 165, 233, 0.14)', to: 'rgba(14, 165, 233, 0)' } as const;
```
Regras: deslocamentos pequenos (≤ 8 px), sem `scale` > 1,03, sem animação em loop infinito.

### Movimento reduzido
- `MotionConfig reducedMotion="user"`: o `motion` desativa animações de transform/layout quando o SO pede movimento reduzido, mantendo opacidade/cor.
- Para animações imperativas (ex.: `animate()` do contador na story 2.3), o componente deve usar `useReducedMotion()` e pular direto para o valor final.
