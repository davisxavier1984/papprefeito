# Story 2.4: Feedback de edição na tabela financeira e indicador de autosave

## Status

Draft

## Story

**As a** consultor que preenche a "Perda Recurso Mensal" de cada recurso,
**I want** ver de forma sutil quais valores foram recalculados após cada edição e saber com clareza se minhas alterações estão pendentes, sendo salvas, salvas ou com erro (com opção de tentar de novo),
**so that** eu confie que o que digitei foi persistido — e que o relatório PDF gerado em seguida reflete os valores atuais — sem que nenhuma animação atrapalhe a digitação.

## Acceptance Criteria

1. **Correção pré-requisito — autosave com valor atual:** ao confirmar uma edição (Enter ou blur) no `CurrencyInput`, o payload enviado por `useAutoSave` contém o array de perdas **já com o valor recém-digitado** (hoje `triggerSave()` usa `dadosEditados` do render anterior — closure desatualizada — e o último valor editado não é persistido; ver Dev Notes).
2. **Estados do autosave:** `useAutoSave` passa a expor, além dos campos atuais (`triggerSave`, `status`, `isSaving`, `isSaved`, `isError`, `error`), o estado `pending` (edição feita, aguardando o debounce), `lastSavedAt: Date | null` e `retry()` (reenvia o último payload). O debounce continua 2000 ms e o payload `MunicipioEditadoCreate` não muda.
3. **Indicador de salvamento:** o bloco "Status" de `FinancialTable.tsx:224-237` é substituído por `SaveStatusIndicator` com os textos: "Sem alterações" (idle), "Alterações pendentes…" (pending), "Salvando…" (saving), "Salvo às HH:MM" (saved, horário pt-BR) e "Erro ao salvar" + botão "Tentar novamente" (error, que chama `retry()`). A troca de estado usa `AnimatePresence` com fade ≤ 150 ms e o contêiner tem `role="status"` e `aria-live="polite"`.
4. **Destaque sutil após edição:** quando o valor de "Perda Recurso Mensal" de uma linha é confirmado e muda, as células derivadas da mesma linha (Potencial Mensal, Potencial Anual, Diferença Anual) exibem um destaque de fundo (`highlightFlash` de `src/theme/motion.ts`) que aparece e some em ≤ 600 ms. Não há destaque no carregamento inicial nem quando o valor não muda.
5. **Sem roubar foco:** nenhuma animação é aplicada ao `CurrencyInput` nem ao `<tr>`/`<td>` da coluna editável; o foco, o cursor e o texto em digitação nunca são afetados; navegar com Tab entre inputs continua funcionando; não há `layout` animation dentro da `Table`.
6. **Mobile:** a visualização em cards (`MobileCardView`) é extraída para um componente de nível de módulo (deixa de ser recriada a cada render — hoje todos os cards e inputs são desmontados/remontados a cada alteração do store). Os cards entram com stagger (≤ 50 ms entre itens, 200 ms cada) apenas quando chega uma nova consulta, e os valores derivados recebem o mesmo destaque do AC 4.
7. **Acessibilidade dos inputs:** cada `CurrencyInput` da tabela e dos cards recebe `aria-label` descritivo (ex.: "Perda recurso mensal — {nome do recurso}"); o `id` padrão duplicado `'currency-input'` deixa de ser usado sem prop.
8. **Semântica de cor da diferença:** a cor de "Diferença Anual" na tabela e no card mobile passa a ser consistente com `MetricsCards` (diferença > 0 = perda → vermelho/`danger`), **após confirmação do PO** (registrar a decisão no Change Log). Se o PO decidir o contrário, ajustar `MetricsCards` em vez da tabela.
9. Com `prefers-reduced-motion: reduce`: sem stagger nos cards mobile; o destaque vira troca instantânea de cor mantida por ~600 ms (sem animação) ou é omitido; o indicador troca de texto sem fade.
10. **Funcionalidade existente continua igual:** consulta de município; edição com `CurrencyInput` (Enter confirma, Esc cancela e restaura, blur confirma, botão limpar); recálculo imediato de MetricsCards; autosave com debounce de 2 s; geração dos dois PDFs (agora com o último valor salvo); login e admin.
11. `npx tsc -b` passa; lint dos arquivos alterados sem novos erros — `useAutoSave.ts` já tem 2 erros `no-explicit-any` pré-existentes (linhas 48 e 50): não aumentar (idealmente corrigir); projeto ≤ 16 erros; build de verificação em `/tmp`.
12. Plano de rollback documentado (Dev Notes).

### Bug encontrado na revisão (AC 1) — closure desatualizada
`FinancialTable.tsx:71-75`:
```tsx
onCommit={(val) => {
  const sanitized = Number.isFinite(val) && val >= 0 ? val : 0;
  updatePerca(index, sanitized);   // atualiza o store (zustand set síncrono)
  triggerSave();                   // mas triggerSave é o callback do render ANTERIOR
}}
```
`useAutoSave.ts:71-81`:
```ts
const triggerSave = useCallback((overridePerdas?: number[]) => {
  if (!selectedMunicipio?.codigo_ibge || !selectedCompetencia) return;
  const perdas = overridePerdas ?? dadosEditados?.perda_recurso_mensal;   // dadosEditados capturado no render anterior
  ...
  timerRef.current = window.setTimeout(() => { mutation.mutate(payload); }, debounceMs);
```
O payload é montado no momento da chamada com `dadosEditados` antigo, então a edição recém-confirmada não vai para o servidor (só a anterior). Como os PDFs são gerados pelo backend a partir de `codigo_ibge` + `competencia` (`Dashboard.tsx:33-38`) e o endpoint lê as perdas salvas (`backend/app/api/endpoints/relatorios.py:33-37` e `:104-108`, via `municipio_editado_service.get_editado`), o relatório pode sair sem a última edição. **Validar no Network antes de corrigir** e registrar a evidência no Debug Log.

`useUpdatePerdaRecurso` (`stores/municipioStore.ts:309-326`) cria o novo array e chama `setDadosEditados`, que reprocessa `dadosProcessados` e `resumoFinanceiro` (`:120-127`, `:171-224`).

### Código atual relevante
`FinancialTable.tsx:224-237` (indicador atual — sem estado "pendente", sem `aria-live`, erro sem detalhe nem retry):
```tsx
<Space size="small">
  <Text type="secondary" style={{ fontSize: '13px' }}>Status:</Text>
  {isSaving && <Tag color="processing">Salvando...</Tag>}
  {isSaved && status === 'saved' && <Tag color="success">Salvo</Tag>}
  {isError && <Tag color="error">Erro ao salvar</Tag>}
  {!isSaving && !isSaved && !isError && <Tag>Pronto</Tag>}
</Space>
```
`FinancialTable.tsx:44-115` — `columns` em `useMemo` com dependência `[dadosProcessados, triggerSave, updatePerca]` (recriadas a cada edição; `updatePerca` é uma função nova a cada render). O `render` da coluna editável usa `dadosProcessados[index]`. `rowKey="key"` = índice.

`FinancialTable.tsx:123-220` — `const MobileCardView = () => (...)` declarado dentro do componente e usado como `<MobileCardView />` (`:240`): nova identidade de componente a cada render ⇒ remount de todos os cards. Efeito colateral real no mobile: se o usuário estiver digitando no card B quando o autosave do card A muda de status (`saving` → `saved` re-renderiza `FinancialTable`), o input do card B é desmontado e perde foco e rascunho. No desktop isso não ocorre porque o tipo do componente da célula (`CurrencyInput`) é estável.

`FinancialTable.tsx:109-113` (desktop) e `:204-215` (mobile): diferença > 0 → `success`/verde. `MetricsCards.tsx:35`: `const isPerda = Number(total_diferenca_anual) > 0;` → vermelho + Tag "Perda". Pelo store (`municipioStore.ts:191`), `diferenca = perdaMensal * 12` e é sempre ≥ 0.

`CurrencyInput.tsx:131-148` — `Input` do AntD com `prefix="R$"`, `inputMode="decimal"`, sem `aria-label`; `id={id || 'currency-input'}`. Comportamento a preservar: formata só no blur, `Enter` → `commit()` + `onEnter`, `Esc` → restaura `lastCommitted` e dá blur, `allowClear` só com foco.

### Esboço do `FlashOnChange`
```tsx
import { useAnimate, useReducedMotion } from 'motion/react';
const [scope, animate] = useAnimate<HTMLSpanElement>();
const prev = useRef(value);
const reduce = useReducedMotion();
useEffect(() => {
  if (prev.current !== value && !reduce) {
    animate(scope.current, { backgroundColor: [highlightFlash.from, highlightFlash.to] }, { duration: 0.6, ease: 'easeOut' });
  }
  prev.current = value;
}, [value]);
return <span ref={scope} style={{ display: 'inline-block', borderRadius: 4, padding: '0 4px' }}>{children}</span>;
```
Animar só `backgroundColor` (não causa reflow, não mexe no foco).

### Restrições
- Proibido: animar `CurrencyInput`, usar `motion.tr` via `components.body.row`, `layout`/`layoutId` na tabela, `AnimatePresence` em linhas da tabela.
- Não mudar o debounce (2000 ms), o endpoint `apiClient.upsertMunicipioEditado` nem o formato do payload.
- A lógica otimista/rollback de cache em `useAutoSave.ts:26-59` deve ser mantida.

### Rollback
- Commit separado para a correção do autosave (Task 1) e para as animações/indicador (Tasks 2–6). Se o indicador ou o destaque causarem problema, reverter apenas o segundo commit; a correção do payload deve permanecer.
- Desligamento rápido das animações: `MotionConfig reducedMotion="always"`.
